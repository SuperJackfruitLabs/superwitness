## Three questions, one run

A run can leave evidence in several places. We bring the answers together without sanding off the
gaps, so you can ask three plain questions.

**What did it do?** Follow the attempts that executed the run, the agent configuration behind each,
and the spans they left. In the run document, start with `attempts` and `trace`.

**How did the products run?** Read the logs and errors that share the run's id or its trace. In the
run document, that is `log_count` and `errors`.

**Was it any good?** Put gate decisions from SuperPipeline beside the verdicts recorded in
SuperWitness. In the run document, both arrive under `verdicts`.

That gives you one record to investigate instead of a small expedition through several systems.

SuperWitness is a single Go binary and a Postgres database, self-hosted and MIT licensed. Start
with [what it is](/what-it-is/), then [install it](/install/).

<HeadsUp>
  v0.0.13 is the release in production. SuperWitness is meant to stand alone, and this release is
  not there yet: it reads runs from SuperPipeline and attempts from AgentPod, and without them it
  runs only in fake mode, which serves one development run on loopback
  ([Try it without the other products](/install/#try-it-without-the-other-products)). Pages say
  where a feature is on `main` and not yet released.
</HeadsUp>
