# UI building blocks: vibekit or bespoke

Each need, what draws it, and why.

| Need | Uses | Reason |
|---|---|---|
| Edge-page actions (Sign in, Sign out, Try again, Continue, All runs, Rubrics) | vibekit `Button` (primary / secondary / text, `href` for links) | Matches the mockups' `vk-button` in every vibe; keeps 44px targets. |
| Focus layout of the edge pages (one centred column, name above) | bespoke `Panel.svelte` | vibekit has no focus/edge layout; the four vibes draw it differently (SW-SignedOut, SW-Edge). |
| superwitness mark | bespoke `Mark.svelte` | vibekit `Wordmark` is the Super Jackfruit Labs bulb, not the product's eye mark the mockups draw. |
| Refusal line (rate limited, origin mismatch, server error) | bespoke `ErrorPanel.svelte` | vibekit `Notice` draws a titled box; the mockups draw one line (wash in Daylight, "✕" in Paper, ink bar in Studio and Quiet) and it must keep the old exact text. |
| In-shell edge states (run, rubric, page not found) | bespoke `InShell.svelte` | A heading, a line and a link; vibekit `EmptyState` adds its own title level and words. |
| Loading | bespoke `Loading.svelte` | vibekit `Loading` hides its label for screen readers only in Daylight and Paper; the mockups keep the words "Loading…" visible in every vibe with per-vibe placeholders. |
| Empty line | bespoke `Empty.svelte` | One muted line; vibekit `EmptyState` is a page-size block with a title. |
| Warning, info and danger-text tones | `src/lib/tones.css` | vibekit has no warning/info tones or danger text-on-wash; hexes from the artboards. |
| The shell (sections, Menu on a phone, account, sources dot) | bespoke `components/Shell.svelte` | vibekit `AppShell`/`AppNav` draw one layout for all vibes; the mockups draw four (Daylight raised column, Paper ruled ledger, Studio ink rail with labelled icons, Quiet a plain list above the content) and the old app's DOM contract (`nav#nav` "Main", "Menu" with `aria-controls="nav"`, inline block on a phone) must hold. |
| Account control (identity, Appearance, Sign out) | bespoke `components/AccountMenu.svelte` | vibekit `Menu` is a pure action list; this one holds the identity block, swaps to the Appearance control in place, and is drawn open inside the phone Menu block. |
| Appearance control | bespoke `components/Appearance.svelte` on vibekit's model (`accentOptions`, `VIBES`, `appearanceCookie` via `appearance.svelte.ts`) | vibekit `AppearancePicker` is a full page with previews, intro and hints (many words the spec does not list); the mockup's "Appearance open" is a compact panel: Vibe, Theme (Follow the sun, Light, Dark), Accent swatches. |
| Sources dot | bespoke `components/SourcesDot.svelte` | No vibekit equivalent; amber uses `tones.css` warn tones. |
| Vibe on `<html>` | vibekit `VibeRoot` (layout) plus `appearance.svelte.ts` | VibeRoot provides the vibe context vibekit components read; the store also writes `data-vibe`/`data-theme` so a choice lands before effects run. |
| Run status pill (Runs page cards, chips; later the run header and attempts) | bespoke `StatusPill.svelte` | vibekit `StatusPill` is deprecated and maps moods (working, needs, done), not run statuses; `StateLabel` has no success/danger/warning/info tones. Tone map: succeeded and completed success, failed danger, waiting warning, running info, everything else neutral; the word is always drawn ("unknown" when empty). |
| Status chips with counts (Runs page) | bespoke markup in `components/RunsPage.svelte` around `StatusPill` | vibekit `QuickFilter`/`Segmented` are single-choice buttons; the old app's chips are links (`withStatus` URLs) with `aria-current="true"`, text "{status} · {count}". |
| Run tabs (run page) | bespoke `Tabs.svelte`, drawn per vibe from SW-RunTrace-* (Daylight pill strip, Paper small caps on a double rule, Studio accent bar, Quiet underlined links) | vibekit `Tabs` links mode has no `role=tab`/`aria-selected` and no arrow keys; its panels mode uses buttons, not URLs; its `vk-tabs` look is one strip for all vibes. On a narrow screen the strip scrolls, centres the selected tab and fades the edges with tabs past them (`data-more`, as the old app). `Tabs.test.ts` was run red against a vibekit wrapper first. |
| Load more (Runs page; later Transcript, Logs) | bespoke markup with vibekit `Button` (`busy`) | vibekit `LoadMore` needs a `total` and says "N of M shown"; the API pages by cursor with no total, and the old copy is only "Load more" / "Loading…". |
| Daylight page head | vibekit `Sky` (phase from `appearance.phase`) | The Daylight mockups set the h1 in the sky band; the other vibes draw a plain head. The mockup's greeting ("Midday.") is not drawn: not an app word. |
| Tables (Logs, Errors, Attempts) | bespoke `ui/table.css` (`table.sw-table`) | vibekit `DataTable` draws one table look and does not stack rows on a phone; the mockups (SW-Phone-Tables-*) stack each row into a block with the short cells on one line and labelled long values (`data-label`, the header words) below, and the cells hold readable `time` elements with the ISO in `title`, level tags and a wrapping digest. Header row: Time, Level, Service, Message (Logs); Time, Service, Message (Errors); the old Attempts header. Rubrics decided in Part 12. |
| Verdict drawer | vibekit `Drawer` if the 401/evidence tests of Part 11 pass against it, else bespoke | Decided in Part 11, test-first. |
| Span inspector | bespoke `Inspector.svelte` | Non-modal `aside` (no dialog role, no scrim, Escape not captured); vibekit `Drawer`/`Sheet` are modal. Daylight and Quiet make room for it (the shell narrows beside it at >= 1100px), Paper and Studio float it over the page's right edge with an edge and a shadow; full screen on a phone with its head and foot (Cite) fixed and the body scrolling. Close keeps the old word "Close" beside an x icon in every vibe. |
| Span waterfall | bespoke `Waterfall.svelte` | vibekit has no timeline. Keeps the old DOM contract (`ul.waterfall > li`, `label.cite`, `button.span-name` whose name is only the span name); bars placed by percent of the whole trace with a minimum width; an axis of durations (aria-hidden, numbers only: the mockups' "Cite / Span / Duration" headers and legends are words the app lacks); beside the span pane (container narrower than 760px) the axis keeps its ends and the service hides; on a phone tick, name and ms share a line with the bar under them. |
| Key-value list (span facts) | bespoke `KeyValue.svelte` | Same reason as the run facts: vibekit `FactList` has no wrapper per pair, so Daylight's cards and Studio's columns cannot be drawn. |
| Fact list (run facts) | bespoke `components/Facts.svelte` | vibekit `FactList` draws `dt`/`dd` pairs flat in one `dl` (no wrapper per fact), so the per-fact cards (Daylight), ruled cells (Paper, Studio) and the phone grid with Agent across both columns cannot be drawn on it. Words (`unknown`, `in progress`, `unreported`) carry `sw-word` (muted italic), the agent principal `sw-mono` and wraps inside its fact. |
| Source unavailable / read failed box | bespoke `WarnBox.svelte` | vibekit `Notice` draws a titled box; the mockups (SW-RunStates-*) draw one amber line with an optional Try again: Daylight wash with an inset bar, Paper ruled wash, Studio ink bar with a "!" (CSS, silent), Quiet dashed border. Reused by Parts 9-10. |
| Notice / alert | bespoke `ErrorPanel.svelte` (see above) | |
| Appearance picker | bespoke `components/Appearance.svelte` (see above) | |
| Redaction marker in transcript text | bespoke `Redaction.svelte` | vibekit has none. Splits the text on `[redacted:...]` and draws each marker as a `mark` inside the text (ink chip in Daylight/Studio, ruled italic in Paper, dashed outline in Quiet); the text content stays exactly as the hub sent it. |
| Transcript steps (cards) | bespoke `components/TranscriptAttempt.svelte` | Keeps the old DOM contract (`ol.transcript > li[data-kind]`, `.failed`, `aria-current` on the `?seq=` card, `details`/`summary` for reasoning and tool calls). Daylight raised cards (agent message on the accent wash), Paper and Studio a two-column ledger (kind, seq and notes on the left; the actions float at the body's top right), Quiet ruled rows. A failed tool call carries a danger marker and the word "failed". Monospace values wrap (`pre-wrap`, `overflow-wrap: anywhere`). |
| Verdicts list (gates and history) | bespoke `components/VerdictList.svelte` | No vibekit list fits the old DOM (`ul.verdicts > li.verdict[id]`, `.superseded`, in-page `#id` links). Gates are words: the status as sent, the decision or "no decision yet" (never JSON). The read-failure box is `WarnBox` with Try again; Revise is a vibekit `Button`. |
| Who is signed in, for the run page | `lib/me.ts` (context set by the layout) | The layout reads /v1/me; the run route reads it from context and passes `me` to the run view (Revise). |
